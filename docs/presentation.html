1. Problem Tanımı ve Mühendislik Yaklaşımı

Yazılım Geliştirme Yaşam Döngüsünde (SDLC) Statik Analizin Yeri

❌ Geleneksel Yöntemlerin Sınırları

  • Derleme Bağımlılığı: Klasik analiz araçları projenin hatasız derlenmesini gerektirir; eksik bağımlılıklarda çalışmaz.
  • Gözden Kaçan Zafiyetler: Bellek sızıntıları (`RESOURCE_LEAK`), `NULL_POINTER_RISK` ve gömülü şifreler manuel code review süreçlerinde kolayca gözden kaçar.
  • Eylemsiz Raporlama: Mevcut araçlar sorunu gösterir fakat geliştiriciye yapıcı veya otomatize edilmiş bir çözüm sunmaz.

✅ J-Inspector Çözüm Mimarisi

  • Compile-Free AST Parsing: JavaParser altyapısı ile kod derlenmeden sözdizimsel düğümler (Nodes) seviyesinde anında tarama.
  • Dinamik Konfigürasyon Engine: `jinspector.json` dosyası üzerinden dışarıdan kural açma/kapama ve threshold belirleme yeteneği.
  • Shift-Left Security: Hataları ve güvenlik açıklarını canlıya çıkmadan, henüz commit/PR aşamasında engelleme.

2. Sistem Mimarisi ve Teknoloji Yığını

Modüler, Genişletilebilir ve Katmanlı Yazılım Mimarısı

🧩 1. Core AST Engine

  • JavaParser 3.x Integration: `.java` dosyalarını Abstract Syntax Tree'ye çevirir.
  • Visitor Design Pattern: `VoidVisitorAdapter` kullanarak kod düğümlerini (Class, Method, Try-Catch) milisaniyeler içinde gezebilir.

🤖 2. Rules & Config Layer

  • 17 Analyzer Engines: Her analiz kuralı için izole edilmiş dinamik kural sınıfları.
  • JSON Config Manager: `jinspector.json` ile threshold ve rule toggle desteği.

📊 3. Export & CI/CD Pipeline

  • Multi-Format Exporter: Interaktif **HTML Dashboard**, **JSON** ve **Console** raporlama.
  • GitHub Actions: Automated build, self-inspection ve artifact dağıtım hattı.

3. Detaylı Analiz Kuralları Matrisi (17 Aktif Kural)

Güvenlik, Performans, Bakılabilirlik ve Mimari Kod Taramaları

CRITICAL SECURITY & MEMORY

  • RESOURCE_LEAK: Try-with-resources dışında açık kalan akışları bularak bellek sızıntısını önler.
  • SECURITY_THREAT: Hardcoded 비밀/API Key ve SQL Injection risklerini tespit eder.
  • NULL_POINTER_RISK: Doğrudan null hedefe yapılan metot çağrılarını yakalar.

HIGH COMPLEXITY & METRICS

  • CYCLOMATIC_COMPLEXITY: McCabe formülü ($V(G) = P + 1$) ile karar noktalarını ölçer.
  • MAINTAINABILITY_INDEX: Halstead ve LOC ile 0-100 arası sürdürülebilirlik skoru üretir.
  • MUTABLE_STATIC_FIELD: Public static değişkenlerin thread-safety riskini denetler.

MEDIUM DESIGN & CLEAN CODE

  • GOD_CLASS & DEEP_NESTING: Dev sınıfları ve aşırı iç içe geçmiş blokları belirler.
  • DEAD_CODE & DUPLICATE_CODE: Ulaşılamaz blokları ve kopyala-yapıştır kodları tespit eder.
  • COGNITIVE_COMPLEXITY: Okunabilirlik ve zihinsel yük seviyesini hesaplar.

INFO CODE SMELLS & STANDARDS

  • NAMING_CONVENTION: Java isimlendirme standartlarını denetler.
  • EMPTY_CATCH_BLOCK: Yutulan istisnaları yakalar.
  • UNUSED_IMPORTS & MAGIC_NUMBER: Temiz kod standartlarını zorunlu kılar.

4. AI Auto-Fix Motoru ve Canlı Kullanım

Geliştirici Deneyimini (DX) Artıran Otomatik Çözüm Mekanizması

💡 AI Auto-Fix Mantığı ve Çıktısı

HTML raporda her ihlalin yanında geliştiriciye rehberlik eden hazır kod bloğu basılır:

// RESOURCE_LEAK için AI Önerisi:
"💡 AI Fix: Kaynak sızıntısını önlemek için try-with-resources bloğu kullanın -> try (FileReader fr = new FileReader(...))"

// HARDCODED_CREDENTIALS için AI Önerisi:
"💡 AI Fix: Şifre/Token bilgilerini koda gömmek yerine System.getenv(\"SECRET_KEY\") ile okuyun."

💻 CLI Çalıştırma Komutları (picocli)

Proje terminal üzerinden esnek parametrelerle kolayca çalıştırılabilir:

# 1. Projeyi derleyin ve JAR paketi oluşturun
mvn clean package -DskipTests

# 2. Özel konfigürasyon ve format seçeneği ile analizi başlatın
java -jar target/j-inspector-3.0-RELEASE.jar -p . -c jinspector.json -f html -o report
